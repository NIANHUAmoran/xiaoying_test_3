# AI 辅助内容、个人贡献与验证

本项目由 AI 编码助手依据用户提供的第 3 题、解题流程及 GitHub 交付规范完成本地实现。AI 辅助范围包括读题、需求拆解、架构设计、代码、合成资料、对抗测试、CLI 复现、运行记录与文档。

## 开发协作与实现职责

开发时使用了并行 AI 协作：一个分工负责合成知识库、文档检索与上下文主题解析；一个分工独立检查需求和证据守卫；一个分工编写业务及对抗测试，并参与复盘文档。主助手负责运行循环、引用校验、离线策略、真实 HTTP 模型接入、CLI、复现与交付核查，并整合各分工提出的修复。

上述协作发生在开发过程。交付程序运行时由一个模型逐步选择工具，不运行多 Agent，也没有引入 Agent 框架。复用了前题的 dotenv 配置方式和 HTTP 接入约定，相关源码在本目录独立提供，不依赖其他题的文件。

模型负责根据实际检索和读取结果选择补查、读取原文、请求澄清或停止。程序负责验证引用来自已读文档、原文精确匹配、主题相关以及冲突方是否查证完整。最终回答直接呈现验证后的完整原文及文档 ID、版本日期，避免将一个人工标注值脱离原文限定单独作为结论。

## 实际验证与修改

已实际执行 15 个离线 CLI 场景和 35 项单元测试，结果为全部通过，见 [测试结果](../examples/test-results.txt) 和 [离线验证记录](../examples/offline-validation.json)。真实模型验证的范围、路径和最终结果统一记录在 [评估文档](03-evaluation.md)；只有实际归档的模型运行记录才作为真实动态决策证据，离线 Mock 通过不能替代该证据。

开发及评审发现并修复了以下问题：引用字段类型不合法时可能导致异常；具体但资料外的属性被误判为含糊问题；一次工具错误恢复后仍永久阻止资料外结论；多属性问题只回答其中一部分；报销系统问题错误套用产品 FAQ；仅摘取标注值而遗漏旧规废止和现行规则的限定。对应测试既检查正常结果，也检查假引用、未读引用、错误主题、遗漏冲突方、版本日期不能代替优先级、工具失败与执行上限。

测试及核查保留了运行中的失败记录。工具恢复后可以解除当前阻塞，但历史错误不会消失；未完成任务可以保留真正已读的部分原文，不能把这部分资料包装成已查证的确定答案。替换文档内容、消除文档冲突后，答案原文和响应动作也会相应改变。

## 使用边界与个人贡献

合成资料的主题和单事实标注由人工规则维护。精确引用校验防止伪造或错配原文，不等于具备任意自然语言的完整语义蕴含判定能力；关键词和上下文规则也不等于通用企业 RAG 的检索质量评估。程序没有把历史 assistant 的回答当作来源，没有记录模型内部思维过程，Trace 中只保留动作、观察和简要依据。

用户选择题目、要求沿用严格目录规范，并提供本地模型配置。密钥不进入交付材料。用户本人独立代码修改及亲自验收尚无记录，本文件不代填这些贡献；提交前应如实补充自己理解、修改和核验的具体位置与结果。

本次 AI 实现与验证窗口见 [delivery-status.json](../examples/delivery-status.json)，不代表候选人个人用时。GitHub URL、最终 commit SHA 和私有仓库评审权限仍需在最终提交时填写或配置，目前未完成远程发布。
