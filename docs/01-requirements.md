# 用户、目标、范围与成功标准

本项目对应第 3 题“企业知识问答 Agent”。用户是查找制度或产品信息的员工，目标是得到有原文支持、可以核对来源的回答；当资料冲突、缺失或工具不可用时，明确说明缺口并追问或停止。原题末尾的文件上传提示不属于业务功能。

## 输入、输出与边界

输入为问题和可选对话历史，知识库为带文档 ID、版本日期的合成 FAQ 或制度。提供文档检索 `search_documents(query)` 与原文片段读取 `read_document(doc_id)` 两个业务工具。模型逐步选择补查、读取、澄清、回答或停止，运行时核验依据。

交付输出包含 `answer`、`citations`、`conflicts`、`gaps`、`clarification_question`、`status` 与 `trace`。每条引用必须给出实际读取的文档 ID、版本日期和原文片段。模型不能把历史对话、检索标题或未读取文档当作回答依据，也不能凭版本日期自行选择冲突制度。

本题采用结构化合成事实与提取式回答：片段标注主题、标签、值和原文，值必须出现在原文中；回答直接呈现验证后的完整原文，而不是仅输出标注值，避免遗漏条件、例外或现行/旧规限定。实现范围是受控知识库中的事实查询、检索改写和冲突呈现，不声称完成任意自然语言文档的语义蕴含证明。

## 优先级

P0 是依据与引用真实性：无依据不回答、引用与原文一致、冲突不能擅自裁决、工具失败不能伪装成资料不存在。同时完成真实模型驱动的有界动作循环。

P1 是六项必验场景、资料替换后的行为变化、可复制的 CLI、成组输入/输出/Trace 和五份交付文档。界面、线上部署、多 Agent 运行系统、向量数据库和生产级知识治理不在当前实现范围。

## 六项必验与可测成功标准

| 验收项 | 预期行为 | 可以核对的证据 |
| --- | --- | --- |
| 明确答案 | 读取目标原文；如 D01 单独规定报销期限 30 天，依据该片段回答，不添加原文没有的信息 | 回答中的事实值与原文一致，引用 ID、版本和片段准确；Trace 有检索、读取和回答动作 |
| 文档冲突 | D01 为 30 天、D02 为 15 天且没有适用范围或优先级时，读取两份原文并补充查证，列出冲突、请求确认适用制度，不直接回答 15 天 | 引用涵盖两个冲突值，`conflicts` 和澄清问题非空；较新日期没有被当成授权依据 |
| 资料外问题 | 在检索不足以支持答案时改写补查，仍无依据则说明资料缺口，不凭通识编造公司答案 | 无错误引用，无确定业务结论，缺口和停止状态明确 |
| 改写后的相似问题 | 对未直接命中关键词的问法，根据空结果改写为规范检索词，再读取原文作答 | Trace 能看到首轮结果和后续查询参数变化；改写前后的答案依据一致 |
| 上下文追问 | 从历史用户问题补足当前问句的主题，例如从“报销期限”接“在哪个平台提交”，检索提交平台而非重复期限答案 | 相关文档和回答随追问目标变化；历史 assistant 文本未被当作引用证据 |
| 工具失败 | 检索或读取失败时保留已经得到的原文，明确未完成原因；有冲突候选未读成功时不得只凭单份资料回答 | 失败工具结果在 Trace 中可见，成功片段保留，最终不虚报完整查证 |

至少保留正常、资料不足、工具失败三组实际运行材料，并覆盖其余验收点。至少两条真实模型路径应表现不同工具观察导致的查询、读取或回答动作变化。离线 Mock 可验证流程，但不能作为真实模型效果证据；实际结果与文件索引统一记录于 [评估文档](03-evaluation.md)。

## 关键校验与边界

- 只有实际成功读取过的片段可以引用；文档 ID、片段 ID 和整段引用必须与工具返回精确一致。版本日期由读取结果提供，不接受模型自行填写。
- 确定回答要求目标主题的全部相关文档成功读取。只读到 D01 而遗漏 D02、或 D02 读取失败时，不能宣称已消除冲突。
- 同主题出现不同事实值时，视为尚未解决的冲突；版本更晚不自动代表优先适用。当前实现不推断部门制度的法律效力或替代关系，缺范围时向用户确认。
- 对话历史只帮助理解用户在问什么。历史用户主题可以补全省略语，历史 assistant 的回答不构成制度依据；明确的新主题应覆盖旧主题。
- 默认最多 16 个决策步骤；达到上限或模型动作不合法时返回明确未完成状态，保留已读依据及 Trace，不制造确定答案。
- 替换原文与对应事实值后，回答和引用应同步变化；将冲突的两个值改成一致后，后续动作应从澄清转为有依据回答。若改动后标注值已不在原文中，应拒绝语料；若同时出现旧规和新规，回答保留完整原文限定，不仅输出旧标注值。

## 显式假设

知识库是小规模、受控且可枚举的合成资料；主题及事实标注由资料提供方维护，并以原文一致性校验约束。当前的完整覆盖检查针对这份有限语料，不意味着已经搜索整个企业或互联网。QA 状态在单次任务内保存，跨轮上下文由输入历史提供，不要求跨进程持久化会话。具体限制、未验证部分和实际完成情况以评估文档为准。
